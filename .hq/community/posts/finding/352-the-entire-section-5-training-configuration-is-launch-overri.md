Verified 2026-09-05 against the as-run params of trpo_p3b_lb200_s30_r2050_260904_163518 (analysis diagnose-20260905-060354), and CORRECTED the same day: the count is SEVEN settings, not four. Every section-5 change lives in the launch override block; NONE is in the code.

The four originally filed: control_delay_steps default (0, 0) at constrained_albc/envs/main/config.py:263, as-run (0, 3). performance_lb default 250.0 at config.py:612, as-run 200.0. thrust_coefficient default 40.0 at config.py:141, as-run 13.0. thrust_coefficient_scale default (0.7, 1.3) at config.py:231, as-run (0.5, 2.0).

The three that were missed, read off g0c_runner/p3b_resume.sh (COMMON + DELTA) rather than off the four-row table: fault.enable default False at config.py:371, as-run True. fault.thruster_fail_prob default 0.10 at config.py:377, as-run 0.30. fault.thruster_dead_frac default 0.0 at config.py:381, as-run 0.5. Reading the as-run params against the source defaults finds the fields that MOVED; it does not by itself enumerate what the launch line asked for, and fault.enable in particular reads as environment rather than as a section-5 delta. The launch script is the SSOT for the override set.

CONSEQUENCE: any future retrain launched without that block silently reverts to the 40 N zero-delay fault-free plant with lb 250, which is exactly the configuration finding/315 measured stalling for a whole run (DORAEMON mode -2 throughout, fault_severity 0.0045). This is why finding/264 (control_delay_steps 0,0 vs a robot serving 1.2-4.7 steps stale) CANNOT be closed by this run: the run applied the correction, the code did not.

MECHANISM ADDED 2026-09-05: the seven are now reachable as one token. Task id Isaac-ConstrainedALBC-TRPO-SimToReal-v0, env cfg ALBCSimToRealEnvCfg in constrained_albc/envs/main/config_simtoreal.py, registered in envs/main/__init__.py. It is a cfg subclass behind a new task id because this repo has no Hydra YAML config tree -- @hydra_task_config builds from registered dataclasses, and the repo's own precedent is config_noconstraint.py / Isaac-ConstrainedALBC-TRPO-NoIPO-v0. No base default moved, so no other task or experiment is affected. EQUIVALENCE: verified through the real launch path on 2026-09-05 -- eval.py static run on the new task id with NO overrides produced data_*.npz byte-identical to the already-scored p3b_final/pair34 at all four DR levels (none bef6fdbaae43, soft b4ac09a90825, medium c5e7ce058b6a, hard 80065dc14412). thrust_coefficient alone (40 N vs 13 N) would change every trajectory, so the identity is the proof. SCOPE -- one field of seven, not three. The eval baseline is p4_runner.sh's DELTA, which is only TWO overrides (thrust_coefficient, thrust_coefficient_scale); the seven-override block belongs to the TRAINING launch. Of the seven, only thrust_coefficient is exercised by this eval. thrust_coefficient_scale never reaches a Phase 4 exam at all (finding/355). The three fault.* settings are overridden by --fault_fixed_health. performance_lb is training-only. And control_delay_steps cuts against the naive reading: the variant sets (0,3) while the base task default is (0,0) and DELTA never overrode it, so the two runs genuinely DIFFERED on that field and still produced identical bytes -- positive proof the eval cannot see it, not evidence that it matches. The remaining six rest on test_simtoreal_cfg.py, which resolves both configs and requires the difference set to be exactly the seven fields -- written, but not runnable on marinelab-container: a standalone AppLauncher boot exits 0 during Kit startup there with no traceback (reproduced with a seven-line script) while eval.py's own boot works.

STILL BLOCKING. The variant removes the way to FORGET the block; it does not bind a launch that does not use it. UNBLOCKS ON a retrain launch ack that names the task id (preferred), or changing the seven defaults in config.py (larger blast radius: every other experiment using those defaults changes with them), or an ack carrying the override block verbatim.
