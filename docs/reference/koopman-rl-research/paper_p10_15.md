## 2. Mathematically Precise Definitions/Algorithms

- **Continuous-time system**: ẋ = G(x), x ∈ X ⊆ R^{N_x}, G continuously differentiable (17, p.1100).
- **Flow map**: 𝒢^t(x(0)) := x(0) + ∫₀^t G(x(τ)) dτ, well-defined for all t ∈ R≥0 (complete flow) (18, p.1100).
- **Continuous-time Koopman operator**: 𝒦^t : ℱ → ℱ defined as 𝒦^t f = f ∘ 𝒢^t for all f ∈ ℱ, where ℱ is a vector space of complex-valued functions over X, closed under composition with 𝒢^t (19, p.1100).
- **Strongly continuous semigroup conditions** for {𝒦^t}: (1) 𝒦^0 = id; (2) 𝒦^{t1+t2} = 𝒦^{t1}𝒦^{t2} for all t1,t2 ≥ 0; (3) lim_{t→0} ‖𝒦^t f − f‖ = 0 for all f ∈ ℱ (p.1100, unnumbered list under eq 19).
- **Koopman generator**: ℒ_G f := lim_{t→0} (𝒦^t f − f)/t = G·∇f for all f ∈ ℱ (20, p.1100). ℒ_G referred to as "the Koopman generator."
- **Control system (discrete-time)**: x_{t+1} = T_u(x_t, u_t), x ∈ X ⊆ R^{N_x}, u ∈ U ⊆ R^{N_u} (21, p.1100).
- **Infinite input sequence framework** [105]: space l(U) of all infinite input sequences {u_s(i)}_{i=0}^∞; left-shift operator S: l(U)→l(U). Extended state x_s := (x, u_s) ∈ X × l(U); dynamical system x_s^+ = (x, u_s)^+ = (T_u(x, u_s(0)), S u_s) =: L(x_s) (22, p.1100), where u_s(0) is the first element of u_s.
- **Koopman operator for extended system**: 𝒦_L : ℋ → ℋ, 𝒦_L f = f∘L for f ∈ ℋ (23, p.1100), where ℋ is defined over field ℂ with domain X × l(U), codomain ℂ, closed under composition with L.
- **Lifted linear predictor (approximate, for MPC)**: z^+ ≈ Az + Bu, where z is the lifted state from initial z₀ = Ψ(x₀), Ψ: X → R^{N_Ψ} the lifting map (24, p.1100). A, B estimated via EDMD-like method; caution: does not generally capture all information of 𝒦_L, and increasing lifted dimension does not guarantee convergence of lifted trajectories to true nonlinear trajectories (citing [105, Discussion after Corollary 1]).
- **Koopman Control Family (KCF)** [36] — alternative representation not relying on infinite input sequences:
  - Family of constant-input systems {T_û}_{û∈U}: x^+ = T_û(x) := T_u(x, u≡û), û ∈ U (25, p.1100).
  - Any trajectory {x_i}_{i=1}^{m+1} generated by input sequence {u_i}_{i=1}^m and x₀: x_{m+1} = T_{u_m} ∘ T_{u_{m-1}} ∘ ... ∘ T_{u_0}(x₀) (26, p.1100).
  - Koopman operator per subsystem: 𝒦_û g = g∘T_û for all g ∈ ℱ, û ∈ U — this defines the **Koopman Control Family** {𝒦_û}_{û∈U} (unnumbered eq, p.1100).
  - Trajectory function evolution: g(x_{m+1}) = [𝒦_{u0} 𝒦_{u1} ... 𝒦_{um} g](x₀) for all g ∈ ℱ (unnumbered eq, p.1101).
- **Input-state separable model** (KCF on common invariant subspaces, cf. [36, Th. 4.3]): Φ(x^+) = Φ ∘ T(x,u) = 𝒜(u)Φ(x), where Φ: X → ℂ^{N_Φ} is the lifting function and 𝒜: U → ℂ^{N_Φ×N_Φ} is a matrix-valued function; **linear in the lifted state but nonlinear in the input** (p.1101, unnumbered). Popular lifted linear, bilinear, and linear switched models [161] are all special cases of this form (Lemmas 4.4–4.5 of [36]).
- Under suitable conditions the infinite-input-sequence framework [105] and KCF [36] are theoretically equivalent [162] (p.1101).
- **EDMD residual-error minimization for dictionary learning**: minimize_Ψ ‖Ψ(Y) − Ψ(Y)Ψ(X)^† Ψ(X)‖_F (27, p.1101) — combines earlier eqs (6) and (7) [not shown in these pages]. Nonconvex; global optimum not guaranteed; minimizing residual error does NOT necessarily give a close-to-invariant subspace (Fig. 3 counterexample, p.1101).
- **Temporal forward–backward consistency index** [163]: 𝓘_C(Ψ, X, Y) := λ_max(I − K_F K_B) (28, p.1101), where K_F = Ψ(Y)Ψ(X)^† and K_B = Ψ(X)Ψ(Y)^† are the EDMD matrices applied forward and backward in time (29, p.1101). λ_max(·) = maximum eigenvalue. If subspace is Koopman-invariant, forward/backward EDMD matrices are inverses of each other ⟹ 𝓘_C = 0; otherwise 𝓘_C ≠ 0, larger deviation ⟹ larger 𝓘_C (p.1101).
- **Consistency index properties** (p.1102): (1) 𝓘_C ∈ [0,1]; (2) unlike (27), 𝓘_C depends only on span(Ψ), not the specific basis (Fig. 3 illustrates); (3) under change of basis, 𝓘_C = max eigenvalue of a PSD matrix (I−K_FK_B not generally symmetric, enabling common eigensolvers); (4) provides a **tight upper bound on the relative prediction error of EDMD over the entire subspace**, formally √𝓘_C(Ψ,X,Y) = max_{f∈span(Ψ), ‖𝒦f‖_{L2(μX)}≠0} ‖𝒦f − 𝔓_{𝒦f}‖_{L2(μX)} / ‖𝒦f‖_{L2(μX)} (30, unnumbered display, p.1102), where 𝔓_{𝒦f} is the EDMD predictor for 𝒦f (eq 8, not shown) and L2 norm computed on the empirical measure (eq 11, not shown). Minimizing consistency index is equivalent to a robust minimax problem: minimize_{Ψ∈PF} max_{f∈span(Ψ),‖𝒦f‖≠0} ‖𝒦f − 𝔓_{𝒦f}‖/‖𝒦f‖ (30, p.1102) — closed form exists for the max part.
- **Symmetric Subspace Decomposition (SSD)** [31]: given search space Ψ_s, any basis Φ with elements in span(Ψ_s) can be described via matrix C (full column rank) as Φ^T(·) = Ψ_s^T(·)C. Invariance under Koopman operator reflected in data as ℛ(Ψ(X)^T) = ℛ(Ψ(Y)^T) (range spaces equal), rewritten as ℛ(Ψ_s(X)^T C) = ℛ(Ψ_s(Y)^T C) (31, p.1102). SSD finds the matrix C with the maximum number of columns satisfying (31) — i.e., the maximal Koopman-invariant subspace within span(Ψ_s). [31] also provides a data-driven, necessary and a.s. sufficient condition to identify all Koopman eigenfunctions in an arbitrary finite-dim function space (relies on eigendecomposition of K_F, K_B). Haseli and Cortés [32] gave a parallel version of SSD for high-dimensional search spaces.
- **Tunable Symmetric Subspace Decomposition (T-SSD)** [33]: finds a subspace with predetermined error level ε ∈ [0,1] (a tuning variable) specifying the "closeness" (distance) between ℛ(Ψ_s(X)^T C) and ℛ(Ψ_s(Y)^T C), relaxing exact equality (31). ε=1 ⟹ T-SSD ≡ plain EDMD (up to 100% prediction error allowed, i.e., no invariance constraint); ε=0 ⟹ T-SSD ≡ SSD (maximal Koopman-invariant subspace, exact prediction). T-SSD "balances the accuracy and expressiveness (the dimension of the identified subspace)" via ε (p.1102).

## 3. Lifting Function Design

- **EDMD's residual error vs. consistency index — critical distinction** (p.1101, Fig. 3): residual error (27) depends on the **choice of basis** for a subspace S = span(x, sin(x)), and can be made arbitrarily close to zero even for a **non-Koopman-invariant subspace** by choosing basis members like D_β(x) = [x, x+β sin(x)] — a known **failure mode / trivial-solution pitfall**: minimizing EDMD residual error does not guarantee (or even correlate with) subspace invariance. Consistency index does NOT depend on basis choice, only on span(Ψ) — a genuine invariance/quality diagnostic.
- **Optimization-based dictionary learning** (p.1101): NNs or other parametric function families used to minimize EDMD residual error (27) directly; problem is nonconvex, global optimum not guaranteed. Requires access to a large dataset and is "typically only applicable to offline precomputation of the dictionary" (p.1102) — a stated practical limitation on data/compute for NN-based lifting.
- **Consistency-index-based selection is superior for long-term prediction** (p.1102, Fig. 4, pendulum example θ̇,ω̇ = [ω, −9.81 sin θ − 0.1ω]): comparing subspaces learned by minimizing consistency index (28) vs. minimizing residual error (27) — consistency-index-based subspace gives superior long-term prediction because it accounts for ALL (uncountably many) members of the function space rather than only the finitely many members considered in the residual-error optimization.
- **Algebraic search methods (SSD/T-SSD)** provide something optimization methods generally lack: **guarantees on subspace invariance quality** without needing a global optimizer. SSD finds the exact maximal invariant subspace; T-SSD generalizes with a tunable accuracy/expressiveness tradeoff (dimension of identified subspace vs. allowed prediction error) — directly relevant to "how big should the lifted dimension be" dimensionality guidance, though framed as an accuracy-vs-dimension knob rather than a fixed rule.
- Dictionary types named for soft robots specifically (§IV.C, p.1098): polynomial basis functions [142], time-delay embeddings [72],[74], and NN-based approaches [64],[65] — the three canonical lifting-function families reappear here as concrete instances.
- **Spectral/eigenfunction identification**: [31] gives conditions to identify all Koopman eigenfunctions in a finite-dim function space via eigendecomposition of forward/backward EDMD matrices (K_F, K_B) (p.1102) — ties lifting-function search directly to spectral (eigenfunction) recovery, not just prediction accuracy.

## 4. Koopman ↔ Reinforcement Learning / Policy Learning Connections

- **§IV.A Manipulation, RL/imitation shaping** (p.1097): "[128] ... leverages Koopman operators to improve reinforcement and imitation learning in manipulation. In [128], human-demonstrated trajectories are encoded into a human intent model via Koopman lifting, which is then used to shape **reward functions for RL agents**, enabling safe and task-constrained human–robot interaction." — Koopman lifting used to construct/shape RL reward, not as the policy's input representation per se.
- **§IV.A, [40]**: "A deep Koopman framework to learn a compact latent representation of system dynamics from observation-only data is developed in [40]. A linear decoder then maps these latent representations to real-world actions, drastically reducing the amount of action-labeled data required for imitation learning." — imitation learning (not RL directly), Koopman latent → linear decoder → actions, motivated by reducing labeled-action data needs.
- **§IV.C Soft robots, RL surrogate model (p.1098)**: "an intriguing recent application involves using a Koopman-based model as a **surrogate environment for training RL policies** [67]. This approach bypasses the need for difficult-to-construct physical or simulated soft robot environments, leveraging the Koopman model to accelerate policy learning in complex morphologies." — Koopman model used as a learned simulator/dynamics surrogate to train RL policies faster, i.e., a model-based RL role, distinct from lifting policy *inputs*.
- **§IV.A KOROL framework [42]** (p.1097, object-centric/dexterous manipulation): extracts visual object features, applies Koopman rollouts to predict future trajectories in feature space; predictions feed an **inverse dynamics controller** to generate manipulation actions — "offering interpretability and robustness in vision-based manipulation." This is Koopman-predicted feature trajectories driving a downstream controller, not an RL policy encoder.
- **Han et al. [41]** (p.1097): Koopman-based **imitation learning framework** for dexterous hand manipulation; jointly models dynamics of both robotic hand and manipulated object via joint Koopman lifting capturing entangled hand–object dynamics — supports "more accurate and generalizable skill learning" (p.1098).
- No passage in these pages describes Koopman lifting applied directly to a policy's/encoder's *observation input* in the manner the user's proposal (1) suggests (lifting proprio/commands/privileged params into Koopman observables fed into an encoder+policy jointly). The closest analogues found are: (a) Koopman latent as compact dynamics representation feeding a linear decoder to actions [40]; (b) Koopman as RL reward-shaping input [128]; (c) Koopman as RL training-environment surrogate [67]. All three are architecturally distinct from "replace the encoder with a Koopman lifting of observations."

## 5. System Identification Semantics

- The **consistency index and SSD/T-SSD framework** (§V.C) formalize what "system identification" means for Koopman: identifying a **finite-dimensional invariant subspace of the function space ℱ** (a set of observables closed, or near-closed, under composition with the dynamics map), NOT identifying latent physical/environmental parameters. The object being identified is a *subspace/dictionary* and the linear operator (K_F/K_B, or A/B in eq 24) acting on it — a **global surrogate linear dynamics model**, not a parameter-estimation of hidden env variables (p.1101–1102).
- **Uncertainty/robustness handling (§III.F, p.1097)** is explicitly about *model* error (from noisy measurement, limited observability, data scarcity, finite-dim approximation), addressed via: (a) error bounds on DMD/EDMD predictions [84],[122]; (b) Kalman-filter augmented uncertainty models on the lifted observables [61] — "augmented uncertainty estimation facilitated by the Kalman filter was shown to improve the Koopman model estimation"; (c) distributions over observables via an NN [65]; (d) extended state observer integrated into deep Koopman modeling for autonomous vehicles [123]. These are about tracking/reducing *prediction* uncertainty of the learned linear model, not about inferring a compact latent code of environment parameters (i.e., not the "encoder infers hydrodynamic coefficients/currents" semantics the project's RMA teacher performs).
- **Online/adaptive estimation examples** (concrete, p.1099, §IV.D–F):
  - Folkestad et al. [78]: **episodic learning** to estimate Koopman eigenfunction pairs and obtain control inputs **in real time**, handling ground effect during multirotor landing — "a sequence of Koopman eigenfunctions is iteratively learned from data" and "nonlinear control signals are improved from the nominal control law."
  - [86]: NN combined with the Koopman operator to **update both the lifted states and inputs** of the aerial robot with **online measurements** — jointly learns dictionary + bilinear Koopman model for quadrotor trajectory tracking at low altitude.
  - [84]: hierarchical structure refining reference signal to a pretuned low-level controller; "a model of the reference and the actual output of the disturbed robot is learned via Koopman operator theory and is utilized in the outer controller to decrease the effect of environmental disturbance in real time" — this is disturbance-model learning, i.e., online adaptation to an unmodeled disturbance, closest in spirit to "inferring an environment-condition-dependent correction," but still framed as learning an input-output disturbance map, not a compact env-parameter latent.
  - Multiagent systems (§IV.F, p.1099): Koopman operator used to **estimate the disturbed model of agents** within a group, via online adaptation [156] or offline training [157], to maintain formation despite external disturbances — again "estimate a model," not "infer discrete env parameters."
- **No statement in these pages claims Koopman lifting inherently performs implicit system identification of environment/domain-randomization parameters** (e.g., hydrodynamic coefficients, thruster faults) the way an RMA-style privileged encoder does. The system-identification semantics documented here are: (a) identify a linear (or bilinear/switched) operator over a chosen/learned observable subspace that best predicts state evolution, and (b) online-adapt that operator/reference model as new data arrives to compensate disturbances. Nothing here supports "Koopman alone removes the need for an encoder that infers latent env parameters" — the encoder's job (compressing privileged simulation parameters into z) and Koopman's demonstrated job (learning/adapting a linearized *predictive* dynamics model or reward/latent-trajectory representation) are different problems in the surveyed literature on these pages.

## 6. Underwater / Marine / Soft / Aerial Robot Applications

- **Underwater robotics** (§IV.E, p.1099, exactly one mention): "researchers have begun to explore its [Koopman's] potential in underwater robotics, where vehicles must adapt to unsteady and dynamic flow fields [90]. In such contexts, Koopman-based formulations enable linear approximations of otherwise nonlinear hydrodynamic interactions, which can be directly integrated into model-based controllers as linear constraints [89],[150]." — Method: Koopman-linearized hydrodynamic model → linear constraints in a model-based controller (not RL, not encoder replacement). Task: vehicle adaptation to unsteady/dynamic flow fields. Cited refs: [90] (potential/exploration), [89],[150] (constraint integration into model-based control).
- **Soft and continuum robots** (§IV.C, p.1098, extensive): high compliance, adaptability, inherent safety; "highly nonlinear and complex dynamics present substantial challenges for traditional modeling and control." Koopman offers "global linear representations of these otherwise intractable dynamics." Notably, "some soft robots afford collection of rich data under diverse control inputs without the risk of damage—an advantage not easily attained with rigid-body robots." Research activity "surged in the past two years," on both modeling [58],[59],[60],[73] and closed-loop control [25]. Lifting functions used: polynomial basis functions [142], time-delay embeddings [72],[74], NN-based approaches [64],[65]. Control strategies: MPC and LQR "most widely adopted due to their compatibility with the Koopman-linearized models" (e.g., [68],[71]). Also: Koopman-based model used as **surrogate environment for training RL policies** [67] (see §4 above) — bypasses need for difficult-to-construct soft-robot sim/physical environments.
- **Aerial robots** (§IV.D, p.1098–1099): challenges from hard-to-model aerodynamic effects [143], variable wind gusts, ground effects during landing [144], low-altitude flight [145],[146] corrupting nominal models. Methods: Folkestad et al. [78] episodic learning of Koopman eigenfunction pairs for real-time control during multirotor landing (ground effect); [86] NN+Koopman bilinear model for quadrotor trajectory tracking at low altitude; [84] hierarchical structure with Koopman-learned disturbance/reference model refining a pretuned low-level controller in real time.
- **Legged/ground robots** (§IV.B, p.1098): quadruped leg dynamics on deformable terrains [53]; full-body/local leg dynamics via Koopman embeddings across gaits/terrains [50],[131]; Li et al. [50] extended into an MPC framework with incremental domain-shift-robust Koopman embedding refinement; higher-abstraction estimation/planning approaches [52],[51]. Wheeled robots: Koopman-based MPC for navigation over complex terrain [126]; virtual control inputs [46] for rotational/coordinate-transformed dynamics.
- **Autonomous vehicles / driving** (§IV.B, p.1098): vehicle model estimation [133] integrated into MPC [134],[135],[136]; deformable terrain + bump handling with linear vehicle+terrain interaction model [137]; bilinear model formations [138] combined with deep NNs [113]; driver-in-the-loop dynamics [139]; stochastic Koopman within attention-based framework for abnormal behavior detection [140]. Comprehensive survey pointer: [141].
- No mention in these pages of a "6-DOF UUV-manipulator" combined arm+vehicle Koopman application — the underwater mention [90],[89],[150] is vehicle-only hydrodynamics, not manipulator-equipped.

## 7. Limitations, Open Challenges, Practical Guidance

- **Model error sources** (p.1097): "noisy measurements, limited observability, data scarcity, or the inability of finite-dimensional approximations to fully capture complex real-world nonlinear dynamics [121]." Explicitly flagged as important "particularly for applications requiring safety, stability, and real-time performance."
- **Lifted linear predictor caveat for MPC** (p.1100, after eq 24): "it is crucial to keep in mind that since the model does not consider infinite-input sequences, it does not generally capture all the information of the operator 𝒦_L. Even if the dimension of the lifted state goes to infinity, one cannot generally conclude convergence of the lifted linear model trajectories to the trajectories of the nonlinear system" (citing [105, Discussion after Corollary 1]) — a direct, explicit refutation of "just lift into a bigger observable space and it converges to the true dynamics."
- **Input handling is fundamentally harder than autonomous (input-free) systems** (p.1100): "Dealing with systems in (21) from a Koopman operator perspective is significantly more difficult compared to systems without input. This challenge arises from the fundamental distinction between states and inputs: while the state is an intrinsic property of the system that evolves according to its internal dynamics, the input... is not known a priori and can significantly influence the system's evolution."
- **Input-state separable model is linear in state, nonlinear in input** (p.1101) — a structural limitation: one "cannot use the structure of the Koopman operator to represent the nonlinearity in the input as a linear operator" for open-loop systems, since the input doesn't follow predefined dynamics.
- **EDMD residual-error minimization failure mode** (Fig. 3, p.1101): can achieve arbitrarily small residual error on a **non-invariant** subspace depending purely on basis choice — "optimization [27] may yield models unsuitable for long-term prediction." This is a concrete, cited counterexample (linear system x^+=0.6x with dictionary family D_β(x)=[x, x+β sin(x)]).
- **Optimization-based dictionary learning limitation** (p.1102): "they often rely on objective functions that are nonconvex and employ parametric families that lack desirable algebraic structures (e.g., NNs)... although optimization-based methods for dictionary selection can provide superior prediction accuracy, they often require access to a large dataset and are typically only applicable to offline precomputation of the dictionary." — direct practical guidance/limitation: data-hungry, offline-only, no invariance guarantee without a global optimizer.
- **Exact Koopman-invariant subspaces are rare** (p.1102): "capturing complete information about the dynamics are rare. A typical and useful approach is to allow for some error in the model to capture (but inexact) information. However, it is crucial to characterize and tune the approximation accuracy" — motivates the T-SSD tunable-error approach.
- **Legged robots**: "modeling and control remain an open problem" generally; Koopman applications in this area are "still in their early stages, with most evaluations conducted primarily in simulation" though "research activity is rapidly growing" (p.1098).
- **Practical/compute guidance implicit in T-SSD/SSD**: algebraic search methods (SSD, T-SSD) are positioned as an alternative to optimization when guarantees on invariance are needed and a global optimizer isn't available/reliable (p.1101–1102) — i.e., a practical decision point between "optimize (data-hungry, no guarantee)" vs. "algebraic search (guaranteed invariant subspace, given a fixed search-space dictionary Ψ_s)."

## Direct relevance to the user's two proposals (extracted facts only, no endorsement)

**Proposal (1) — lift ALL inputs (obs, privileged params, proprio history, commands) into Koopman observables before encoder+policy:** These pages contain no description of lifting privileged/DR environment parameters or command inputs as "Koopman observables" fed into an RL encoder+policy pipeline. The control-input handling machinery here (§V.B, KCF, input-state separable model) is about the *action/input* u_t of the *robot's own dynamics equation*, not about lifting arbitrary heterogeneous network inputs (privileged sim parameters, command vectors) into one shared Koopman observable space. The paper's input-state separable model is explicit that inputs enter **nonlinearly** even after lifting (p.1101) — undercutting a premise that "lifting makes everything more linear" for actuation/command-like inputs specifically. Also directly on point: eq (24)'s caveat that lifted linear predictors do **not** generally capture all Koopman operator information and do **not** provably converge to the true nonlinear trajectories even as lifted dimension → ∞ (p.1100) — a concrete counter-evidence against "more-linear representation improves implicit system identification" as an assumed benefit.

**Proposal (2) — drop encoder, feed Koopman-lifted obs to policy alone, claiming Koopman itself does system ID:** Nothing in these pages supports the claim that Koopman lifting performs the same function as an RMA-style privileged-parameter encoder. The system-identification-like behaviors documented here are: (a) learning/adapting a linear predictive operator or dictionary over observables (§V.C, EDMD/SSD/T-SSD) — a *dynamics-prediction* fit, not encoding of latent scalar environment parameters (currents, hydrodynamic coefficients, thruster faults) into a compact z; (b) online disturbance-model adaptation in real time for aerial/multiagent robots ([78],[84],[86],[156],[157], p.1099) — closer to a correction/adaptation mechanism, but framed as learning an input-output or reference-tracking correction, not as inferring discrete privileged parameters used to compute reward/cost in simulation. Where Koopman does connect to RL/imitation in manipulation, it plays three different, narrower roles: reward-shaping input [128], compact-latent-to-action decoder replacing action-labeled imitation data [40], and RL-training surrogate dynamics model [67] — none of which is "replaces the encoder that infers env parameters for asymmetric-critic RL."
