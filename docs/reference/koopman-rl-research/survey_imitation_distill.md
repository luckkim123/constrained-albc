## Koopman Operator Integration — Imitation / Distillation with Koopman Latents

### 1. Han, Xie, Zhao, Ravichandar — "On the Utility of Koopman Operator Theory in Learning Dexterous Manipulation Skills" (KODex, CoRL 2023, oral)

**Mechanism.** Lifts the joint hand+object state into a higher-dimensional linear observable space (a Koopman dictionary over robot joint state and object pose) and fits a Koopman operator matrix analytically (least-squares over demonstration trajectories, in the EDMD family — no gradient descent, no neural network training loop for the dynamics model itself). The fitted linear operator generates a reference/desired state trajectory for the hand+object; a separate downstream controller tracks that trajectory to produce joint commands. This is a per-task, closed-form system-identification approach to behavior cloning, not a learned neural encoder.

**Evidence.** Tasks: Door Opening, Object Relocation, Tool Use, In-Hand Reorientation (Adroit-hand suite). Baselines: NN, LSTM, NDP (Neural Dynamic Policy), NGF (Neural Geometric Fabric). Reported qualitatively (I could not decode the paper's PDF table through WebFetch — the PDF stream did not render as text — so exact percentages below are not independently verified, only the qualitative comparison from a search snippet is): comparable success rate and sample efficiency to SOTA IL, "an order of magnitude faster" to fit/train, and more consistent/predictable across seeds because there is no gradient-based initialization sensitivity. A search-indexed summary states KODex wins on Door Opening while NGF wins on Relocation and In-Hand Reorientation, i.e., no uniform win.

**Maturity.** Published, oral at CoRL 2023, code released (`GT-STAR-Lab/KODex`).

**Applicability to our stack: NOT-APPLICABLE** — KODex is an analytic, per-task linear system-ID method fit on privileged, fully-observed demonstration replay; it has no mechanism for encoding a noisy, partially-observed real-sensor history under heavy domain randomization (its Koopman operator is fit once per task from clean demo trajectories, not trained across a DR distribution or conditioned on observation history). It solves a different problem than "map o_t history → z-hat under partial observability."

### 2. Chen, Abuduweili, Agrawal, Han, Ravichandar, Liu, Ichnowski — KOROL: "Learning Visualizable Object Feature with Koopman Operator Rollout for Manipulation" (CoRL 2024)

**Mechanism.** Lifts a *learned* observable ϕ(x) = [robot state + polynomial basis of robot state, learned visual object features from a CNN + polynomial basis of those features]. A Koopman matrix K is fit by least-squares over ϕ(x(t)) → ϕ(x(t+1)) and is **re-fit periodically during training** (every ~50 epochs) as the feature extractor changes. Critically, the feature extractor is trained end-to-end via a **multi-step rollout-consistency loss**: propagate the lifted state forward N steps autoregressively through the (fixed, current) Koopman operator and penalize squared error against the ground-truth robot state trajectory — this is what forces the learned visual features to be "Koopman-friendly." Actions are produced by a separate, pre-trained, task-specific inverse-dynamics controller that consumes the Koopman-rolled-out robot-state sequence — the Koopman module never outputs actions directly.

**Evidence.** ADROIT sim (200 demos): Door 99.9%, Tool Use 100%, Relocation 100%, Reorientation 86.4% for KOROL, vs. NDP (99.9/96.9/99.8/64.6) and Diffusion Policy (100/100/99.2/93.3). KOROL beats NDP by 1.08× and Diffusion Policy by 1.16× averaged across tasks. Real-world (20 trials/task, 50 demos): Toy Relocation 20/20, Teapot Pickup 19/20, Cube Insertion 14/20. Multi-task (ResNet34, 800 combined demos): Door 100%, Tool use 99.9%, Relocation 93.8%, Reorientation 86.8%.

**Maturity.** Published, code/arXiv available (arXiv:2407.00548).

**Applicability to our stack: STRETCH.** The reusable idea is the **multi-step rollout-consistency loss** — it is exactly the kind of "linear-dynamics regularizer trained purely off existing supervised targets" the assignment asks about: propagate z-hat forward N steps through a learned linear operator and penalize the deviation from the teacher's actual future z-sequence (already logged in the DAgger dataset — no new label source, no new loss class, just a multi-step extension of the existing z-matching term). Two blockers: (a) KOROL fits one global K per task on a fixed dynamical regime; our teacher's z is a function of 28D domain-randomized physical parameters (hydro coeffs, payload, thruster faults) — a single linear operator representing z-dynamics faithfully across that whole DR distribution is unverified and is the central risk; (b) KOROL's action path is a separately-trained inverse-dynamics controller decoupled from the Koopman rollout, which does not match our end-to-end action+z joint DAgger objective, so only the *consistency-loss* piece transfers, not the full architecture.

### 3. Bi, Lim, Chen, Huang, Soh — KOAP: "Imitation Learning with Limited Actions via Diffusion Planners and Deep Koopman Controllers" (ICRA 2024/2025, arXiv:2410.07584)

**Mechanism.** A "plan-then-control" split: (1) a diffusion planner trained on **observation-only** trajectories proposes a target future-state trajectory (planning horizon k=8, receding-horizon execution of 4 steps); (2) a Deep Koopman controller tracks that plan and outputs low-level actions. The controller has four parts: a Koopman encoder g_θ (MLP, state → latent), a linear Koopman matrix K_θ (governs one-step latent transition), a **latent-action predictor f_θ — an LSTM over a state-history window x_t^τ** (structurally identical to our GRU-over-o_t-history), and a linear action decoder d_φ mapping the latent action to real continuous actions, trained **only on the action-labeled subset of data**. Joint training loss = reconstruction (`‖g_ψ(g_θ(x_t)) − x_t‖²`, an autoencoder term) + Koopman one-step consistency (`‖K_θ·g_θ(x_t) + f_θ(x_t^τ) − g_θ(x_t+1)‖²`) + action-decoder regression (`‖d_φ(f_θ(x_t^τ)) − a_t‖²`, action-labeled data only).

**Evidence.** D3IL benchmark, 5 manipulation tasks, success rate vs. fraction of action-labeled data (1%/5%/25%): Avoiding 78.0/97.2/97.5%, Aligning 80.3/86.1/92.0%, Sorting 61.7/61.4/65.8%, Stacking 27.2/33.9/45.6%. KOAP outperforms Decision Diffuser, plain Diffusion Policy, a VAE baseline, and LAPO across nearly all regimes, with the largest margin at 1% action labels. Real robot (scooping task, 100 human + 100 kinesthetic demos): KOAP 50–60% success vs. 20–40% for baselines.

**Maturity.** Published, code released (`jxbi1010/KOAP`).

**Applicability to our stack: STRETCH — closest structural match, but with a hard constraint conflict.** KOAP's latent-action-predictor (LSTM over a state-history window → latent, then decoded to action) is architecturally what our GRU-over-o_t-history already is, and its per-timestep linear Koopman-consistency term on the encoder is precisely the "linear-recurrence-as-regularizer, trained supervised on existing targets" mechanism the assignment is probing — it could in principle be added as `‖K·z_hat_t − z_hat_{t+1}‖²` scored against the teacher's already-logged z_{t+1} target, adding no new label source and, in isolation, no new *loss class* (still a regression term against an existing target, just at an adjacent timestep pair instead of pointwise). **However**, KOAP's own recipe bundles this consistency term with an autoencoder **reconstruction loss** — exactly the aux-loss family already tried and rejected on this project's encoder (empirically causing z-collapse/decoder-ignoring-z). Importing KOAP wholesale would reintroduce the banned loss class; only a reconstruction-stripped, consistency-only variant is admissible under the settled decision, and that stripped variant is untested — neither in KOAP's own ablations nor here. Its evidence axis is also not our failure mode: KOAP is validated under *scarce action labels at train time*, not *degraded/held observations at deployment* (our real ≤25 Hz bus with ZOH); the two are structurally adjacent (both are "a supervisory signal is sparse relative to the state stream") but the transfer of "linear consistency helps" from one axis to the other is an analogy, not demonstrated evidence.

### Cross-cutting assessment for the teacher→student pipeline

None of the three is drop-in ready under the project's existing constraint (no new aux-loss class on the encoder). The one mechanism common to all three that is genuinely reusable within that constraint is a **multi-step or one-step linear self-consistency term computed purely against already-available z/action targets** (KOROL's rollout-consistency, KOAP's Koopman-consistency minus its reconstruction term) — i.e., add `‖K·z_hat_t − z_hat_{t+1}‖²` (or an N-step rollout version) as an extra supervised regression term on the GRU's output, using logged teacher z-sequences that are already there. This is a small, targeted experiment (not a re-architecture) worth flagging as a candidate probe rather than an adopted recipe, since the load-bearing assumption in every source paper — that a single (or slowly-updated) linear operator adequately represents the latent's dynamics — has never been tested against domain randomization this heavy (28D physical-parameter randomization + discrete thruster-fault regime changes), and a discrete fault-switching regime is exactly the kind of nonlinearity plain linear Koopman operators are known to struggle with without careful dictionary design (none of the three papers deals with fault/regime-switching dynamics).

**Verdict summary**

| Paper | Verdict | One-line reason |
|---|---|---|
| KODex (CoRL 2023) | NOT-APPLICABLE | Per-task analytic system-ID on privileged, fully-observed demos — no history-conditioned partial-observability mechanism, no DR generalization pathway. |
| KOROL (CoRL 2024) | STRETCH | Rollout-consistency loss is reusable as a supervised multi-step z-matching term, but a single global linear operator across our full DR distribution is unverified. |
| KOAP (ICRA 2024/25) | STRETCH | Architecture (LSTM-over-history → latent → action) matches our GRU almost exactly and its Koopman-consistency idea is extractable without new aux-loss class, but its recipe bundles a reconstruction loss we've already rejected, and its evidence is on a different scarcity axis (few action labels, not degraded deployment observations). |
